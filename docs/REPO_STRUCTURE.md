# Repository Structure

This repository is organized around a small Python package plus runnable scripts,
examples, tests, and local experiment artifacts.

## Source

- `aims_agent/` contains the importable package.
- `aims_agent/agent.py` is the high-level orchestration entry point.
- `aims_agent/model_strategy_analysis.py` runs dataset profiling, feature-selection
  evaluation, model comparison, UQ evaluation, and report generation.
- `aims_agent/uncertainty_evaluator.py` wraps `uncertainty-toolbox` metrics in a
  project-local interface.
- `aims_agent/probabilistic_models/`, `probabilistic_trainer.py`,
  `probabilistic_visualizer.py`, and `uq_workflow.py` contain probabilistic and
  uncertainty-aware workflow support.

## Scripts

- `scripts/analyze_matsci_strategy.py` runs the data-analysis and strategy report
  workflow.
- `scripts/run_materials_robustness.py` is the generic robustness entry point for
  missing-value strategies, outlier strategies, repeated CV, UQ calibration, and
  feature-stability evidence.
- `scripts/llm_materials_strong_loop.py` is the generic LLM-guided evidence loop.
  It writes uncertainty notes and evidence JSON, asks the LLM for the next
  experiment plan, then repeats until the evidence is strong or the iteration
  limit is reached.
- `scripts/run_spall_robustness.py` and `scripts/llm_spall_strong_loop.py` are
  compatibility entry points for the original spall-strength workflow.

## Data

- `data/` contains checked-in example and real materials datasets.
- `data/real_data/` contains larger real-data files used by the materials
  workflows.
- Do not write generated experiment outputs into `data/`; use `results/`.

## Examples And Tests

- `examples/` contains small runnable demos and configuration examples.
- `tests/` contains unit and integration tests.
- `pytest.ini` defines the test configuration.

## Generated And Runtime Artifacts

- `results/` is for local run outputs and is ignored by Git.
- `logs/` is for local dependency or runtime logs and is ignored by Git.
- `catboost_info/` is generated by CatBoost and is ignored by Git.
- `generated_code/` contains generated components. Some historical generated
  components are tracked, so do not blanket-delete or blanket-ignore the
  directory.

## Hygiene Rules

- Keep new reusable logic inside `aims_agent/`.
- Keep one-off command-line workflows inside `scripts/`.
- Keep small, explanatory runnable snippets inside `examples/`.
- Keep run outputs under `results/`.
- Avoid committing caches, `.DS_Store`, virtual environments, logs, and model
  library runtime folders.
